## Recover your work after the export window

The shutdown date has passed, so begin with an inventory. Do not upload the only copy of an old export into the first tool you test.

### If you have a Height export

1. Duplicate the original file and keep one copy read-only.
2. Record the format, export date, workspace name, and expected project count.
3. Inspect a sample of tasks, comments, owners, statuses, dates, attachments, and links.
4. Create a mapping from Height fields to the candidate tool.
5. Import one small project or rebuild it manually.
6. Compare record counts and inspect the awkward records before moving more.

An import that succeeds can still lose meaning. A status may map to the wrong column. A former user may become plain text. Comments may lose authorship. Attachments may remain as dead links. Count and inspect.

Ask each vendor whether it supports your exact export format today. Do not assume a generic CSV importer understands Height’s relationships.

### If you do not have an export

Rebuild active work, not the whole historical workspace.

Start with systems that linked to Height:

- Git repositories and pull requests can reveal open implementation work.
- Product documents may contain project scopes, owners, and decisions.
- Calendar events can identify current milestones and review dates.
- Team messages may hold links, blockers, and decisions that never reached another system.
- Customer systems can reveal promised work and unresolved requests.

Create one recovery board with three groups: confirmed active, needs owner confirmation, and archive reference. Assign a person to every recovered active item. If nobody can explain why a task still matters, do not make it active by default.

Preserve old Height URLs as reference text even if they no longer resolve. The URL may still appear in messages, commits, or documents and can help connect records during recovery.

## Avoid the expensive migration mistakes

The first mistake is choosing the product with the longest feature table. A broad suite can still be wrong for the five actions your team performs every day.

The second is importing the full archive before testing current work. Old tasks inflate search results, create unclear owners, and make record-count checks harder. Keep the archive protected and move active records first.

The third is rebuilding custom fields without an owner. Every new status, view, automation, and permission creates a rule somebody must maintain. Start with the smallest model that can run the pilot.

The fourth is trusting a successful import message. Verify counts, authors, dates, attachments, links, and status mapping. Open records that contain unusual characters, long comments, missing owners, or deleted users.

The last mistake is running two live systems without naming the source of truth. During a pilot, decide whether Height’s recovered archive is read-only and whether the candidate tool owns new status. People should never wonder which copy to update.

### Protect customer and company data

Old exports may contain private comments, attachments, email addresses, and access details. Store them according to your current data policy. Remove credentials before sharing a sample with a vendor or support team.

Give the migration worker access only to the data it needs. If an AI agent helps classify tasks, define which fields it may read and where its output can be stored.

## Run a one-week replacement pilot

Choose one live project that resembles the work Height used to hold. Avoid the easiest demo project and the messiest company-wide program.

For one week, measure:

- Time to create, assign, and update an ordinary task.
- Whether the team can find decisions and current status without asking in chat.
- How much configuration the workspace owner performs.
- Whether external agents can work without a person relaying every update.
- How reviewers find completed work and request changes.
- Which old Height behavior people still miss after real use.

Keep the candidate only if it improves the daily workflow. A successful import into a product people avoid is another stale board.
